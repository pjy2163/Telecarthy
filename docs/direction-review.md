# 데모 구현 방향 검토

현재 범위는 같은 도로·방향의 참여자 매칭과 상대 수락 후 1대1 음성 통화입니다. 기능 추가보다 이 흐름의 실제 동작과 재현 가능한 검증을 먼저 완성합니다.

## 유지할 방향

- 차량용 네이티브 앱을 주 화면으로 사용하고 브라우저는 상대 차량 테스트 도구로 구분합니다.
- WebSocket은 매칭·요청·수락·종료, WebRTC는 실제 음성 전달을 담당합니다.
- 수락 전에는 마이크를 통한 통화 음성을 보내지 않고 종료·연결 장애 시 미디어를 정리합니다.
- 가상 위치, 버튼으로 시작하는 음성 인식, 실제 Pleos TTS 연동 상태를 화면과 제출 문서에 구분합니다.
- 게시본의 통신 키와 서명 비밀번호는 환경변수로 받고 키 파일·장비 경로·개발 캐시는 저장소에서 제외합니다.

## 검증 결과 해석 시 확인할 항목

현재 `scripts/native-audio-test.mjs`는 앱의 `media-metrics.json`을 읽어 송수신 바이트가 일정 값 이상인지 검사합니다. 이 파일은 통화 종료 후에도 남을 수 있고, 다음 통화의 첫 측정값이 쓰이기 전에 읽히면 이전 통화의 값을 새 통화의 성공 근거로 사용할 수 있습니다. 검토 시점의 측정값에는 통화 ID와 측정 시각이 없습니다.

최종 검증에는 현재 통화 ID 또는 테스트 시작 이후의 측정 시각과 바이트 증가를 확인하는 조건이 필요합니다. 양쪽 클라이언트의 현재 통계도 함께 확인합니다. 이 항목이 해결되기 전에는 해당 파일만으로 두 번의 통화가 모두 검증됐다고 단정하지 않습니다. 구현 코드는 별도 개발 작업에서 보완할 항목입니다.

## 후속 차량 연동 범위

FusedLocation 기반 실제 위치, Gleo를 통한 핸즈프리 명령, CarUxRestrictions 연동과 주행 중 사용 허용 범위는 현재 정지 상태 데모와 구분합니다. Android SpeechRecognizer 버튼 입력을 Gleo 연동 또는 완전한 핸즈프리 기능으로 표현하지 않습니다.

Pleos TTS 초기화 성공은 서비스 연결의 증거입니다. 실제 음성 안내 재생과 차량 오디오 우선순위 동작도 별도로 확인합니다. 양방향 RTP 수신은 네트워크를 통한 오디오 전달의 증거이며, 사람이 들을 수 있는 음질과 차내 소음·에코 검증을 대신하지 않습니다.
